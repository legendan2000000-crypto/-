# 배차일보 웹앱 (1단계)

**보는 앱이 아니라 직접 입력해서 쓰는 배차 작업 도구.**
지금 실제로 쓰는 배차일보(`26년배차일보_정리.xlsx`, 2026년 5,935건)를 **기초 데이터베이스**로 얹고,
그 위에 매일 배차를 입력·수정하며 쓴다. 프레임워크 없는 단일 HTML — 나중에 Firestore로 이관한다.

## 실행

- 배포/개발용 멀티파일: `app/index.html` (같은 폴더에 `data.js`, `vendor/` 필요)
- 배포 단일파일: 루트의 `배차일보.html` — 파일 하나만 열면 됨 (data·pdf.js 인라인)

```
python tools/extract_dispatch.py 26년배차일보_정리.xlsx   # data.js 생성 (실데이터라 gitignore)
python tools/build_singlefile.py                          # → 배차일보.html
```

## 화면

- **당일배차 (첫 화면)** — 실시간 전이라 **가장 최근일** 하루가 기본. ◀▶로 날짜 이동, 그날 배차를 시간순으로. 각 건 편집·삭제·복제. `＋ 새 배차`로 입력.
- **＋ 입력** — 직접 입력 폼. 상단 **빠른 입력**(메신저 붙여넣기 / D/O·PDF 드롭)으로 폼을 자동으로 채운 뒤 검토·저장.
- **요약** — 차량·날짜·화주·청구처·선사·구분 기준 집계(기간 지정).
- **조회** — 전체(기초DB+내입력) 통합검색·엑셀식 필터·CSV. 별칭 관리.

## 입력을 돕는 것들

- **메신저 붙여넣기 → 자동 파싱** — 필터 없이 통째로 붙여넣으면 컨번호·날짜·시간·수출입·연락처·차량·상차/하차·B/L을 정규식으로 뽑아 폼에 채움. **확신 낮은 칸은 노란색**(사람이 확인). 자동 확정 안 함.
- **D/O·PDF 읽기** — 텍스트 PDF는 브라우저에서 바로 추출해 파싱. 스캔 이미지/사진은 실제 앱에서 **Claude Vision**으로 판독(서버 중계). 지금 샘플은 텍스트 PDF까지.
- **차량 뒷4자리 자동기입** — 숫자를 치면 기초DB의 차량 목록에서 후보를 띄우고, 고르면 자차/용차 구분과 최근 샤시를 채움. (전체 차량번호 완성은 KYSS 마스터 붙일 때)
- **화주 자동완성** — 화주를 고르면 최빈 주소·연락처·청구처를 채움. 사업장이 여러 개면 버튼으로 선택.
- **컨번호 실시간 검증** — 타이핑 중 ISO 6346 체크디짓 판정: 정상 ✓(초록)·오기입 ✕(빨강 "번호를 다시 확인하세요")·형식오류(주황). 정상이면 다음 칸으로 이동.
- **별칭 검색토큰** — 거래처·지역 별칭을 앱 켤 때 곱해 검색 토큰 생성. `청주SDI`·`오창SDI`처럼 지역+화주로 검색. 별칭은 조회 화면의 `별칭 관리`에서 편집(localStorage).

## 저장

- 입력·수정·삭제는 **브라우저 localStorage**에 저장(영속). 새로고침해도 유지.
- 기초DB(5,935건)는 원본 보존 — 편집하면 **수정본**으로 저장하고 원본은 그대로 둔다(태그: 신규/수정).
- 실시간 공유·동시편집·인증·계정별 금액권한은 Firestore 이관 시.

## 한계 (샘플)

- 데이터가 브라우저 로컬. 여러 명이 같이 못 봄(그게 Firestore 이관의 목적).
- 이미지 OCR은 API 필요(실앱 Claude Vision). 파싱은 규칙 기반이라 애매한 값은 노랑으로 표시만.
